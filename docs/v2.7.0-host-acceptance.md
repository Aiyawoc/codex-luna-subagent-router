## 10. Targeted retest after the first v2.7.0-alpha.1 Host report

The first real Host report exposed two accounting/reporting defects and one unconfirmed cross-turn concern. A candidate containing the fixes must run these targeted checks before Decision Shadow acceptance.

### R1 — Sequential reuse receipt intervals

Reuse the same Materialized Worker for two sequential bounded tasks under the same parent session.

Require:

- Worker lifetime usage may grow cumulatively (example: 45k → 90k);
- receipt A remains frozen to the first task interval;
- receipt B reports only the second task interval, not the 90k lifetime total;
- binding receipt B must not mutate receipt A;
- the same receipt can never be rebound to another Worker;
- if upgrading from a historical single-`receipt_id` row without a frozen prior baseline, the next reused receipt must report `receipt_baseline_missing` rather than inventing a delta.

### R2 — Project report attribution independent of child CWD

Create Workers from a project-scoped Lead while allowing the Host to run child work with a different effective CWD.

Require:

- the exact `parent_id + agent_id` may be linked to the project outcome receipt even if the hook-derived Worker scope differs;
- `router report --project-root <repo>` includes the linked Worker;
- the report uses the receipt's fixed project scope as authoritative attribution;
- the same receipt/identity safety checks remain enforced;
- no absolute child CWD is persisted solely to repair attribution.

### R3 — Missing reuse baseline cannot expand the old turn

If the current Host still does not emit/persist a usable `UserPromptSubmit` begin, first verify the Stop-only recovery path rather than fabricating a start boundary:

- first Stop without a prior exact boundary must create a registered turn with `main_turn_baseline_missing` / unknown, never lifetime totals;
- a later Stop may use the previous exact persisted end boundary as its start cursor;
- reused child accounting may use only the previous exact child end cursor;
- record whether the row came from normal submit registration or Stop recovery.


Exercise:

```text
Turn A child has known partial/lifetime usage
→ Turn A seals
→ the child baseline is unavailable at Turn B begin
→ same child is reused and lifetime usage grows
→ late terminal/Stop arrives
```

Require:

- Turn A remains frozen at its previously known interval;
- Turn A never absorbs Turn B's cumulative lifetime count;
- Turn B is conservatively `child_baseline_missing` / unknown when its baseline cannot be proved;
- unknown is not replaced with zero.

### R4 — Planning telemetry failure classification

For a project-scoped plan, if the default `${CODEX_HOME}/state` planning ledger is not writable, the Router may fall back to the project's `.codex/codex-luna-subagent-router/state/planning.jsonl`. `router report --project-root` must merge default and project-fallback observations by `plan_id` without double counting. A lock conflict must remain a lock failure and must not be hidden by switching stores.


When a natural planning telemetry write failure occurs, preserve:

```text
permission_denied
state_unavailable
lock_failed
io_error
invalid_observation
unknown
```

Require:

- production plan remains unchanged/fail-open;
- the machine-readable error code contains no local path or prompt/source content;
- do not fabricate a more specific cause when the Host exposes insufficient evidence.

## 11. Release Decision

Do not merge/release v2.7.0 if any of the following occurs:

- local cheap evidence creates unnecessary Workers;
- deep independent analysis is collapsed back into the Lead merely to reduce Worker count;
- non-materialized Workers are counted active;
- runtime failure contaminates model-quality calibration;
- Decision Shadow changes production route/plan;
- schema 2.0 upgrade loses existing calibration/token/custom settings;
- Token/Outcome reporting invents zero values or claims simulated savings as observed savings.

When all automated CI/Portable Runtime gates and mandatory real-host rows pass, record the exact candidate commit and acceptance evidence before marking PR ready for merge.
