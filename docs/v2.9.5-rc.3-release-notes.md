# Agent Router v2.9.5-rc.3 · Lean Delegation

**发布类型：候选版（prerelease），不是v2.9.5正式稳定版。**

## 更新概览

本版基于v2.9.5-rc.2，保留GPT-6.2 Sol/Astra和GPT-6.1 Terra max模型白名单。重点从自建完整Token计数转向更早分派和Worker完整工作包交付。

- 全新安装默认`token_accounting=off`，使用Codex本身可用的用量视图；**升级保留已有on/off、Hook、Decision/Radar授权和全部历史数据**。旧版Token计数、报告及手动导出保留为可选兼容，不自动删除或迁移。
- `adaptive`在真实声明了完整交付边界时，可把低/中风险、完全可验证、有write_paths的浅层实现、测试和局部修正交给一个Worker。`adaptive_aggressive`继续作为明确可选的积极委派模式；不改变用户选择、不强制达成份额。
- 新增`router delegation_stats [--all-scopes] --json`：只读取规划、Outcome与新的轻量关联账本，不读取Token、会话内容或外部API。分别显示候选、计划ready、已有回执及独立验证交付。计划不等于真实spawn，回执也不是Host权威身份字段。
- `route_advisor begin`新增可选`--plan-id`与`--worker-id`。仅在Host已确认Worker Materialized后使用；核对相同scope、ready状态、task-id、模型和effort。新关联单独写`delegation-links.jsonl`，**不修改旧Outcome/receipt格式**；旧账本全部保留。
- Skill入口要求在最小项目证据形成后、Lead进行深入实现前扫描有价值的分派机会。保留micro、机械查询、权限、冲突、健康探针、单波3 Worker上限、独立复核、精确模型证据与失败隔离等边界。

## 升级及回滚

使用与OS/CPU匹配的完整发行包并验证SHA256；根据`references/codex-guided-install.md`选择`upgrade`，不切换`fresh`。升级不会强制关闭旧Token Hook；希望停止旧采集必须另行明确授权并审查Hook变更。旧数据不随安装覆盖。

新增规划行带有旧版未定义的可选字段。回滚rc.2前应备份完整状态，旧版可能无法统计这些新规划行；`delegation-links.jsonl`对旧版本不可见，但不会覆盖旧Outcome及receipt数据。

## 验收边界

源代码自动测试、Arena规划审计、包/插件安装及升级回滚门禁、四平台CI必须通过后再认为发行包可用。真实Codex Desktop对Host Hook信任、Worker Materialization、最终实际model+effort和实际委派收益需要单独实机验收。

本候选**不声称已经实现30%/50%的Token委派比例、不声称节省额度，也不把规划中ready Worker视为真正启动的Worker**。Decision Shadow仍是Shadow；Radar保持原有opt-in及授权边界。
