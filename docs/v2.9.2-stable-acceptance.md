# Agent Router v2.9.2 — Stable Acceptance / Evidence Boundary

Date: 2026-10-29. Stable target: `v2.9.2`, promoted from the tested `v2.9.2-rc.1` with source-only version, release documentation and release-workflow note updates.

## Scope

v2.9.2 includes previous v2.9.1 RC.1–RC.4 accounting, lifecycle, Windows descriptor and model-source changes together with optional GA Decisions Shadow and the seven-question guided installer. No additional automatic Worker model, unverified native authority or new hook trust is enabled by this promotion.

## Required release gates

The final **pure-semver Stable commit on main**, not only a prior RC SHA, must successfully pass:

1. Strict `MANIFEST.sha256` verification against every tracked source file, full Python 3.12/3.13 source regressions and deterministic Router Arena.
2. Windows x64 / Windows ARM64 / macOS Intel / macOS Apple Silicon complete-package builds, including pinned bundled Python and its licenses.
3. Per-platform offline launcher, integrity, install/upgrade and staged Q5 hook compatibility regression with Unicode-path coverage and the seventh decision-provider installation question.
4. Default four-event native plugin build, core-file identity, pre-activation inertness, migration/deactivation/rollback tests; separately verify optional six-event plugin in CI but do not publish it as an enabled default.
5. Eight default distribution archives (four complete and four native plugins) plus individual SHA256 checksums and a consolidated `SHA256SUMS` before marking the GitHub Release non-draft.
6. Never re-use RC package SHA256 for Stable: versioned tar/ZIP metadata and package manifests must identify `2.9.2`.

The Stable release workflow fails if either the tag or release already exists, requires an exact `release/v2.9.2` branch at `main` HEAD, and will not publish partial asset sets.

## Remaining field checks, not blockers for bounded Stable claim

- Native macOS Keychain/Windows Credential Manager per-user prompt permissions on a real Desktop launch (do not test with live user secret in CI).
- Exact Codex Desktop/Host version, plugin loading and trust decisions; live Shadow checkpoint activation and credentials available to the actual host process.
- Real requested-versus-observed Worker model/effort identity, full accounting completeness and controlled comparative workload evidence.

All of these remain **NOT VERIFIED** until observed; the release must not silently claim them.

## Decision

The version is eligible for Stable publication **only if the final main SHA passes the dedicated Release workflow with all eight packages and checksums**. If any job fails or a tag is already present, hold publication for review rather than bypassing gates or force-moving tags.
