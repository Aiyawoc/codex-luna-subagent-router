# Agent Router v2.8.0 — Stable Acceptance

Date: 2026-09-30

## Release decision

v2.8.0 is accepted for Stable publication with the Agents API backend remaining explicit opt-in, read-only/shadow, non-authoritative and unable to promote itself automatically.

The Stable decision is based on the v2.8 RC package gates plus real Codex Desktop lifecycle evidence. The Native authority readiness threshold remains a separate future promotion gate.

## RC and package evidence

- v2.8.0-rc.2 source regression suite: 467 / 467 PASS.
- RC.2 Manifest: 160 / 160 tracked files PASS.
- Router Arena: PASS.
- RC.2 portable build/smoke: Windows x64, Windows ARM64, macOS x64 and macOS ARM64 PASS.
- Clean installed package `doctor --verify`: PASS, bundled CPython 3.13.15, 1783 files verified.
- Report export to an explicitly writable output directory: PASS.
- The final Stable workflow must repeat source, Arena, Manifest and all four portable package gates on the exact final `main` commit before publication.

## Real Desktop lifecycle evidence

### Completed Worker and natural reuse

A real Luna Worker completed naturally, then was naturally reused in the next parent turn with the same Worker identity.

Turn A:

- child baseline: `fresh`;
- exact child end boundary known;
- complete child snapshot: 138,936 total tokens.

Turn B:

- same Worker identity;
- no new Worker identity required for the reuse;
- child baseline: `exact_cursor`;
- new child turn observed;
- exact child end boundary known;
- complete incremental child snapshot: 108,470 total tokens.

Observed Worker lifetime change was 247,406 - 138,936 = 108,470, with the component token fields agreeing with the incremental child snapshot. Worker lifetime terminal completeness could remain partial independently; the frozen parent-turn interval itself was exact and complete.

### Post-Stop historical freeze

Turn A and Turn B both sealed. Turn A's Worker identity, child turn, fresh baseline, end boundary, complete snapshot and snapshot timestamp remained unchanged after Turn B reuse. Later Worker usage did not extend the historical Turn A interval.

### Real interrupt lifecycle

A separate real Worker was observed in Host `running`, then interrupted through the Host interrupt mechanism. The interrupt request reported `previous_status=running`; subsequent Host queries reported `interrupted` repeatedly. This is accepted as `confirmed_interrupted`, not as an interrupt request being mistaken for a terminal.

Router could not recover that interrupted Worker's transcript/end boundary, so its usage remained `unavailable` with all token counts `null`. No zero values were invented.

The original interrupt Desktop session later became unavailable. Therefore a strict same-session next-parent-turn isolation replay is `NOT VERIFIED`. After the interrupt turn, five later registered parent turns across two other sessions contained zero boundary/snapshot references to that Worker, so no cross-session contamination was observed. The unavailable original session makes this a documented evidence limitation, not a claim of same-session proof.

## Route Economics and cost review

RC.1 exposed an `unknown != 0` bug: an empty economics scope returned `estimated_usd=0.0`. RC.2 fixed the representation:

- zero estimated attempts => `estimated_usd=null`;
- report renders unknown cost as `-`;
- real estimated attempts continue to produce numeric estimated cost;
- incomplete per-route estimates keep route and average cost `null`.

Real historical all-scope data continued to estimate numeric cost after the fix. Cost Review remains observational, `authoritative=false`, `routing_unchanged=true`, `automatic_override=false`.

## Host and Native authority boundary

- Host transport remains network-denied unless `--allow-network` is explicit.
- Native Shadow evidence never overwrites Desktop canonical accounting.
- Agents API evidence remains non-authoritative.
- `automatic_promotion=false`.
- The default 10 clean usage evidence + 3 resolved lifecycle evidence readiness gate is retained for a future Native authority promotion review.
- Current absence of enough real Agents API evidence does not imply Native authority and is not represented as a successful readiness result.

## Installation integrity note

During RC field testing, Serena was accidentally activated on the immutable installed Skill directory and wrote `.serena/**` metadata/cache files. `doctor --verify` correctly rejected that package as an integrity mismatch. The package was restored through a clean installation and later `doctor --verify` returned `status=ok`.

The Stable package does not whitelist external-tool files inside the installed package. Code navigation/indexers should target a source checkout or temporary copy instead.

## Stable boundary

Accepted for v2.8.0 Stable:

- Desktop v2.7 planner semantics and Execution Shape behavior;
- `gpt-6-luna → gpt-6.1-sol → gpt-6-astra` new automatic Worker family;
- exact completed-Worker reuse interval accounting and Post-Stop historical freeze;
- real interrupt request/terminal distinction with unknown usage preserved as null;
- Host Backend and Agents API adapters in shadow/non-authoritative mode;
- receipt-bound Route Economics and conservative Cost Review as shadow observability only.

Not promoted in v2.8.0 Stable:

- Agents API usage/lifecycle as canonical accounting authority;
- automatic Native authority promotion;
- automatic cost-based route override;
- Decision Shadow authority.
