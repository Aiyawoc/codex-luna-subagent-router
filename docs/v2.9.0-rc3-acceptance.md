# Agent Router v2.9.0-rc.3 — Cross-root Upgrade Preflight Acceptance

Date: 2026-10-05

## Why RC.3 exists

RC.2 corrected which installation root upgrade preflight used when reconstructing expected Router-managed hooks. Real package testing then exposed a second boundary in the same read-only path.

When RC.2 preflight ran from a staging complete package and tried to describe the handler belonging to the existing RC.1 complete-package installation, `configure_token_accounting.hook_handler()` called `runtime_support.validate_runtime()` for the installed RC.1 root. That validator correctly requires actual execution of a bundled package to use that root's bundled interpreter. Because the running process belonged to the RC.2 staging root, preflight exited before it could return Q5 JSON.

## RC.3 behavior

The distinction is now explicit:

- **execution/configuration path:** bundled runtime affinity remains mandatory;
- **read-only preflight description:** Router may reconstruct the exact expected command for another detected installed bundled root without pretending the current process is executing that root.

The descriptive path still uses the target installation's own bundled Python path, isolation flags, `runtime_dispatch.py`, hook version, project-root arguments and owner metadata. It does not execute that Python, mutate hooks or grant trust.

## Required blocker re-test

Before upgrading an existing RC.1/RC.2 installation, run the released RC.3 staging package:

```text
bin/router inspect_guided_install --install-mode upgrade --json
```

For an existing valid hooks installation, this command must:

- exit 0;
- return JSON;
- report `UserPromptSubmit`, `Stop`, `SubagentStart` and `SubagentStop` in Q5 `current_hook_events`;
- report Q5 `needs_question=false`;
- omit `5` from `pending_questions`;
- leave routing, hooks, trust and historical ledgers byte-identical.

After that passes, perform the normal RC.3 upgrade and repeat the same inventory from the installed package. Staging and installed results must agree.

## Negative boundary

The fix must not weaken runtime execution safety.

Automated regression requires that calling the normal `hook_handler()` for a different bundled installation from the current staging interpreter still fails with the bundled-interpreter affinity error. Only the explicit read-only descriptor used by install inventory may bypass that current-process affinity check.

A Router-owned hook pointing at the staging copy while another complete installation is detected also remains stale rather than being accepted by owner marker alone.

## Automated release gates

The exact RC.3 release commit must pass:

- full unit/integration suite including the two-root bundled regression;
- Manifest exact tracked-file coverage;
- Router Arena;
- complete-package install/upgrade/hooks/full-test smoke on Windows x64, Windows ARM64, macOS x64 and macOS ARM64;
- within each complete-package smoke, create installed Router-managed hooks and then run upgrade inventory from the separate staging package, requiring all four Q5 events and no pending Q5;
- native-plugin migration/deactivate/rollback smoke on all four targets;
- SHA256 verification for all eight release archives.

## Remaining Stable evidence

RC.3 only addresses the confirmed upgrade-preflight blocker. Structured app-server event access, exact-version Host capability observations, PTC positive-path evidence, fixed-workload benchmark data and real Desktop plugin loading remain evidence questions, not automatically promoted claims.

The RC.2 field run already provided useful partial real lifecycle evidence for natural Worker reuse, finalized historical freeze, interrupt terminal status and unknown-usage null semantics. Those observations should be retained in the final Stable review, while any unverified component remains explicitly unclaimed.
