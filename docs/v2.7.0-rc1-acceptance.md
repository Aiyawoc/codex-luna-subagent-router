# Agent Router v2.7.0-rc.1 — Final Real Host Acceptance

> Feature freeze: no new Core behavior is permitted in RC.1.  
> Basis: v2.7.0-alpha.4 plus release/documentation cleanup only.  
> Decision Engine must remain off for this Core pass.

## Gate 1 — Sol Lead H3 fresh-wave

Use GPT-6 Sol as Lead in a fresh Host session and a bounded task with two genuinely independent reasoning siblings. Do not manufacture extra work solely to increase Worker count.

Require:

1. initial runtime health is `unknown`;
2. planner selects a first real Worker as `health_probe_worker_id`;
3. spawn acknowledgement alone is not counted as active;
4. after the Host exposes a real Worker identity/status, that Worker is treated as Materialized;
5. runtime health becomes `healthy`;
6. remaining dependency-ready sibling(s) are released without another artificial probe;
7. only Materialized `PendingInit/Running` Workers count in `open_workers`;
8. runtime initialization failure, if naturally observed, does not create a quality-calibration outcome;
9. actual Worker model/effort is recorded; do not infer it from role text.

PASS only when the fresh-wave transition is observed on the real Host. If the Host cannot expose sufficient lifecycle evidence, report NOT VERIFIED rather than guessing.

## Gate 2 — Cross-turn reused Worker frozen boundaries

Use one real Materialized Worker across two sequential parent turns in the same workflow when the Router/Host naturally permits reuse.

Required sequence:

```text
Turn A
→ Worker W is used
→ parent Stop/seal freezes exact parent and child end boundaries

Turn B
→ the same Worker W is reused
→ Turn B starts from Turn A's frozen exact child end cursor
→ Worker lifetime usage grows
→ Turn B records only its new interval
```

Require:

1. Turn A remains frozen after Turn B begins;
2. Turn A never absorbs Turn B's later cumulative Worker lifetime;
3. Turn B uses only the prior exact frozen child end cursor as its reuse baseline;
4. Turn B reports only the new interval;
5. unknown/missing boundaries remain unknown and are never replaced with zero;
6. receipt interval accounting remains consistent with the turn interval;
7. no manual ledger editing, fake hook payload, or synthetic Token counter is used.

If the Host does not naturally reuse a Worker, report NOT VERIFIED rather than forcing unsafe state.

## Minimal regression checks

Do not rerun the entire Alpha acceptance suite. Confirm only:

- installed version is `2.7.0-rc.1`;
- `doctor --verify` passes;
- Decision Engine is off;
- no unexpected non-GPT-6 automatic Worker is observed;
- `router report` remains readable;
- existing user routing/hooks/ledgers are preserved by upgrade.

## Stable release decision

RC.1 is acceptable for promotion to `v2.7.0` only if both Gate 1 and Gate 2 are PASS and no new Core regression is observed.

Decision Shadow calibration and a fixed Token/elapsed-time savings percentage are not stable-release blockers and must not be presented as verified Core savings.
