# Agent Router v2.7.x — Grounded Decision Layer 最终计划与执行文档

> 状态：最终设计基线  
> 基线版本：v2.6.7  
> 目标首发：v2.7.0  
> 核心原则：用户选择的主 Agent 不被静默替换；Decision Engine 只提供语义决策证据，确定性 Router 和运行时继续掌握路由、权限与执行权。

## 1. 目标

v2.6.7 已完成主动委派机会扫描，但是否进入委派规划、如何给六轴分类、是否存在多个独立分析方向，仍主要依赖 Astra/Sol Lead 自己完成管理型 reasoning。Lead 可能在已经读取足够证据之后继续亲自搜索/分析，直到较晚才形成 Worker 候选。

v2.7.x 引入可选的 **Grounded Decision Layer**：Lead 先完成最小必要取证，再把少量已确认事实投影成 bounded decision dossier，交给 Jev、Laya-compatible API 或其它 compatible provider 返回 typed decisions + confidence。Decision Engine 不直接 spawn Worker、不直接改变权限，也不静默替换用户选择的 Lead；provider 不可用、低置信或结果无效时完整回退到 v2.6.7 行为。

最终定位：

> Astra/Sol 负责理解代码发生了什么；System-1 帮助决定下一笔推理预算应该花在哪里；Python Router 负责最终规则约束与执行规划。

## 2. 与 jev-codex-router 的取舍

参考：https://github.com/0xNatoshi/jev-codex-router

吸收：bounded decision dossier、typed `choice/score/noul`、Decision Lease、shadow mode、kill switch/fail-open、decision telemetry、通用 `POST /ask`、工具结果短摘要。

不采用：per-call 静默切换主 Agent、让 Jev 直接拥有最终 model/effort 路由权、transport fork/LiteLLM 作为必需依赖、忽略 confidence 的生产路由。

本项目保持：

```text
用户选择 Astra / Sol Lead
        ↓
Lead 身份稳定
        ↓
Decision Engine 只提供证据
        ↓
route_advisor.py 决定最低足够 Worker 能力
        ↓
plan_work.py 处理并发、依赖、冲突
        ↓
Luna / Sol / Astra SubAgent
```

## 3. 最终状态机

```text
GROUND
  ↓
CHECKPOINT
  ↓
DECIDE
  ↓
PLAN
  ↓
EXECUTE
  ↓
VERIFY
  ↓
COMPLETE
```

- **GROUND**：Lead 完成 Minimum Evidence Pass，只获取足够判断问题结构的证据。
- **CHECKPOINT**：确定性 helper 判断是否值得进入 Decision Layer，不调用模型。
- **DECIDE**：Decision Provider 回答六轴、Opportunity、Meta Decisions，并给出 confidence。
- **PLAN**：`route_advisor.py` / `plan_work.py` 保持最终 deterministic routing authority。
- **EXECUTE**：Codex native SubAgent 执行实际工作，Worker 仍不得递归创建 Worker。
- **VERIFY**：判断是否需要 independent verifier / regression scan。
- **COMPLETE**：结果进入现有 Outcome Registry、Token accounting、report。

## 4. Decision Layer 的调用位置

不在用户 Prompt 到达后直接让 Jev 猜模型，也不在 Astra/Sol 已经完成大部分分析之后才调用。

正确位置：

```text
用户任务
→ Lead 定位入口
→ 读关键文件/调用链/错误
→ 获得最小事实集合
→ Decision Checkpoint
→ Jev/Laya
→ 组织后续探索/委派/验证
```

即：**Grounding 后、深入 Exploration 前。**

## 5. Minimum Evidence Pass

只回答：入口、相关模块、已确认事实、候选假设数量、错误/测试/日志信号、预计是否跨模块或高上下文。不要求完整根因、完整代码摘要、长篇翻译或最终修改方案。

建议机器状态：

```json
{
  "active_task": "Diagnose NPC creation latency during continuous movement.",
  "stage": "grounded",
  "modules": ["network", "entity_queue", "visibility"],
  "facts": [
    "NSY arrival appears timely",
    "entity creation enters a deferred queue",
    "queue has a per-frame budget"
  ],
  "uncertainties": ["visibility-range interaction is not verified"],
  "signals": {
    "tool_errors": 0,
    "candidate_hypotheses": 2,
    "cross_module": true
  }
}
```

Decision state 默认使用英文短句；代码符号、路径、错误码、标识符原样保留。不要为了调用 Decision Engine 生成长篇英文总结。

## 6. Bounded Decision Dossier

新增 `scripts/decision_state.py`，代码优先构造状态。

建议字段：

```text
schema_version
checkpoint_id
task_family
active_task
stage
modules
facts
uncertainties
tool_summary
error_signals
hypothesis_count
cross_module
changed_paths_summary
verification_summary
```

预算：`active_task <= 400 chars`；facts 最多 8 条、每条 <= 240 chars；uncertainties 最多 6 条、每条 <= 240 chars；tool result 只保留数量、错误数量和最多 3 个短摘要；默认目标 <= 8 KiB，hard cap 32 KiB。不发送完整源码、完整日志、完整 tool output、完整对话。

## 7. Decision Checkpoint Detector

新增 `scripts/decision_checkpoint.py`。它是本地 deterministic helper + Skill 执行契约，不声称具有 transport proxy 那种“每次模型调用必经 Router”的强制能力。

### 触发条件

非 micro 任务命中任一：候选根因 >=2；跨 2+ 模块；即将开始第二轮大范围 read/search；tool error 改变原假设；substantial implementation 前根因仍不确定；存在 2+ 独立 sibling；继续探索会明显扩大 Lead context；进入最终 verification 前需要判断 independent verifier。

### 不触发

micro edit；单文件已知根因机械修改；一次修改+一次测试即可完成；已有有效 Decision Lease 且未发生失效事件。

输出示例：

```json
{"decision":"checkpoint_required","reason_codes":["multiple_hypotheses","cross_module"]}
```

## 8. Decision Provider 抽象

新增 `scripts/decision_provider.py`：

```text
DecisionProvider.evaluate(state, questions)
→ DecisionResponse
```

首批 provider：

- `off`：禁用；
- `jev`：直接 TypeSafe System One API；
- `http`：generic compatible HTTP provider；
- `jev_ask`：兼容 `jev-codex-router POST /ask`。

Laya 本地/云端只需实现 compatible HTTP contract，即可走 `http` provider。标准发行包不捆绑 Laya 权重、PyTorch、Transformers 或 ONNX runtime。

统一请求：

```json
{"state":{},"questions":{}}
```

支持 question type：`choice`、`score`、`noul`。统一响应正规化为 provider/model/available/latency_ms/answers/optional diagnostics。

## 9. 问题集合

### 六轴

保持现有：`task_kind`、`task_scope`、`reasoning_depth`、`verifiability`、`failure_cost`、`context_volume`。Decision Engine 只给语义建议，不直接给最终 route。

### Delegation Opportunity

```text
evidence_scout_worthwhile
parallel_siblings_likely
independent_analysis_worthwhile
independent_review_worthwhile
context_isolation_worthwhile
```

### Meta Decisions

```text
more_evidence_required
multiple_plausible_hypotheses
cross_module_causality
parallel_analysis_worthwhile
lead_should_continue_directly
```

### Decision Lease

候选：`checkpoint`、`evidence_phase`、`user_turn`。

## 10. Decision Lease

`checkpoint` 仅当前判断有效；`evidence_phase` 可覆盖同一干净取证阶段；`user_turn` 可覆盖当前稳定 user turn。

任一事件使 lease 失效：新用户 turn、tool error 改变假设、主要 hypothesis 增删、investigation→implementation、implementation→verification、compaction 改变关键证据边界、provider 要求重新取证、Lead override、TTL 超时。

Lease 只缓存语义 Decision Evidence，不缓存权限、Worker slot、依赖、冲突等实时状态。

## 11. Authority 与 Confidence Gate

权威顺序：Lead 负责理解任务/证据；Decision Engine 提供 typed semantic evidence；`route_advisor.py` 掌握 model/effort/capability policy；`plan_work.py` 掌握 dependency/conflict/capacity；Codex runtime 掌握实际 spawn/permissions；tests + Outcome Registry 证明结果。

Decision Engine 永远不直接 spawn/stop Worker、修改文件、批准权限、改 sandbox、改并发、静默替换 Lead。

实验默认 confidence band：high >=0.85；medium >=0.65；low <0.65。阈值必须由真实 eval 调整。v2.7.0 Shadow 不使用 confidence 改变生产路由。

## 12. Fail-open、Kill Switch 与隐私

Decision Engine 是 optional enhancement。未配置 provider、缺 key、timeout、401/402/429/5xx、invalid schema、unsupported answer、confidence 不可验证等都统一为 `unavailable`，然后保持 v2.6.7 行为。

远程 provider 只发送 bounded dossier + typed questions。Decision Ledger 禁止保存完整 prompt、assistant 回复、源码、完整文件、完整 tool output、完整日志、API key、真实绝对路径。允许记录 checkpoint_id、scope hash、task_family、provider/model、decision version、answers/confidence、latency、lease、accepted/overridden/unavailable、reason code、router result、outcome receipt id。

## 13. Token / 成本目标

Shadow 阶段不宣传节省 Token；Advisory 主要验证可靠性和更早委派。真正 Token 收益只在后续 High-confidence Fast Path 出现：高置信且 deterministic policy 无冲突时，Lead 可以跳过重复的 Opportunity/六轴管理型 reasoning。

关键指标：Lead Token / verified task、Total Token / verified task、cached input rate、Worker Token share、verified fail、under-route、decision latency、provider availability。

## 14. v2.7.0 首发范围

必须交付：Decision Provider interface；`off/jev/http/jev_ask`；bounded dossier；checkpoint helper；六轴+5 Opportunity+Meta questions；Decision Lease；Shadow Mode；Decision ledger；report 的 confidence/latency/disagreement/availability；Outcome Registry 非敏感关联；HTTP fail-open；`jev-codex-router /ask` compatibility test；四平台 portable runtime 回归；默认关闭时与 v2.6.7 行为等价。

v2.7.0 不交付：High-confidence 自动 Fast Path；Decision Engine 直接改变最终 route；内置 Laya；PyTorch/Transformers/ONNX；transport proxy；自动切换 Lead；provider outage 下替代主模型。

## 15. routing.json 演进

建议 schema 2.0 → 2.1，并兼容旧 2.0：

```json
{
  "schema_version": "2.1",
  "routing_mode": "adaptive",
  "cost_objective": "minimize_expected_total_cost",
  "context_budget_policy": "minimal_sufficient",
  "result_budget_policy": "concise_sufficient",
  "max_concurrent_workers": 3,
  "decision_engine": {
    "enabled": false,
    "mode": "shadow",
    "provider": "off",
    "endpoint": null,
    "api_key_env": null,

    "confidence_high": 0.85,
    "confidence_medium": 0.65,
    "lease_enabled": true
```

缺失 `decision_engine` 等价 disabled；升级不得自动开启远程 provider；key 只允许 env/protected credential，不写 routing.json；用户明确选择远程 provider 后才允许发送 dossier。

## 17. 测试与 Eval

Provider 测试：valid Jev、`/ask` compatible、timeout、401/402/429/5xx、invalid JSON、incomplete distribution、unsupported answer、missing key、custom endpoint。

State 测试：dossier 上限、长 tool output 摘要、error-first、不泄露源码/key/完整 prompt、代码符号/path 不被错误转换。

Checkpoint 测试：micro 不触发；multiple hypotheses/cross-module/second exploration wave 触发；valid lease 抑制重复 Decision；hypothesis change 和 verification transition 使 lease 失效。

Integration：disabled 与 v2.6.7 路由一致；shadow 不改变 model/effort/worker plan；provider unavailable 不改变 route；provider 不可绕过 luna_only、permission、capacity、conflict、verified-history calibration。

Advisory 前建立约 200–300 个代表性 fixture，覆盖 micro、bounded implementation、scan/research、ordinary debug、deep cross-module debug、race/lifecycle/ordering、architecture、independent review、parallel sibling。Eval 必须关联 verified outcome、retry、Lead rework、under/over-route、Token、latency、confidence calibration，而不是只看“和 Lead 是否一致”。

## 18. v2.7.x 启用闸门

- **v2.7.0 Shadow**：生产路由完全不受 Decision Engine 影响。
- **v2.7.1 Eval/Reporting**：报告 availability、decision count、confidence、disagreement、lease hit、latency、outcome、Token baseline。
- **v2.7.2 Advisory**：Lead 可接受/覆盖 Decision，覆盖必须记录 reason code；仍不自动改变最终 route。
- **后续 Fast Path**：只在真实数据证明后启用，初始限定 verifiability=yes、failure_cost!=high、非 architecture、非 permission/external side effect、high confidence、deterministic policy 无冲突。

## 19. v2.7.0 执行里程碑

### M0 — 契约冻结

冻结 DecisionRequest/Response、provider enum、question schema、ledger schema、routing.json 2.1、fail-open contract。要求旧 2.0 兼容且不改生产 route。

### M1 — Provider Core

实现 `decision_provider.py`、Jev direct、generic HTTP、`jev_ask`、timeout/schema validation。所有失败返回 unavailable，不新增第三方 Python dependency。

### M2 — Grounded State + Checkpoint

实现 `decision_state.py`、`decision_checkpoint.py`、dossier budget、lease、phase transition。要求 state bounded，micro/known-cause 不产生不必要 Decision。

### M3 — Shadow Runtime

实现 Shadow Decision、decision ledger、Outcome receipt association。开启/关闭 Shadow 的实际 Worker plan 必须一致；provider 断网不影响任务。

### M4 — Report / Observability

`router report` 增加 availability、confidence、disagreement、latency、lease hit、linked outcomes、provider usage。unknown 不写成 0，JSON/CSV/Markdown 不导出 prompt/source。

### M5 — Guided Install / Portable Runtime

增加 inspect/configure decision engine、用户显式选择 provider、credential/env 指引、四平台完整包。升级 v2.6.7 默认 Decision Engine off。

### M6 — Real-task Acceptance

真实 Astra/Sol 任务覆盖单文件机械修复、多模块 debug、多假设分析、implementation+verifier、大范围 repo scan。确认 Shadow 无行为改变、checkpoint 不过度触发、dossier 足够、provider failure fail-open、report 能对齐 Outcome 和 Token。完成后才能发布 v2.7.0。

## 20. v2.7.0 发布验收

必须全部满足：VERSION 单一来源；Decision Engine 默认关闭；routing.json 2.0 升级行为不变；Shadow 不改变 route/plan；provider 不可用不影响 Router；不捆绑 Laya/PyTorch/Transformers；credential 不进入 ledger/report；dossier 有硬上限；ledger 不保存用户正文/源码/完整日志；`jev-codex-router /ask` fixture 通过；所有原测试和新 Decision tests 通过；complete manifest 通过；Windows x64/ARM64、macOS x64/ARM64 portable runtime 全绿；至少一轮真实 Astra 和一轮 Sol Lead Shadow 验收通过。

## 21. 不做事项

不重新引入 Terra 到当前三层 Worker policy；不做主 Agent 自动切换；不做 transport proxy/Codex 私有协议 fork；不内置 Laya；不为了 Jev 使用率强制增加 Decision；不为了 Worker 数机械增加 SubAgent；不把 confidence 当成功概率；不以 shadow/backtest 直接宣称实际 quota 已节省。

## 22. 最终成功标准

可靠性：Decision Engine unavailable 时保持 v2.6.7 等价行为。

路由质量：verified_fail 和 under-route 不增加；复杂任务漏委派减少；independent verifier 更合理。

Token：进入后续 Fast Path 后，Astra/Sol Lead Token / verified task 下降，Total Token / verified task 不恶化，避免的 Lead exploration 大于 Decision Layer 额外成本。

长期架构保持：

```text
LLM           → 理解事实
System-1      → 辅助分配推理预算
Deterministic → 路由/约束/调度
Runtime       → 执行
Outcome/Test  → 证明结果
```

## 23. 最终决策

v2.7.0 先交付 Grounded Decision Layer 基础设施和 Shadow 观测，不让 Jev/Laya 接管生产路由。在真实 Outcome 与 Token 数据证明高置信结果可靠后，才逐步允许它承担重复的六轴/Opportunity 管理型判断。

该路线同时保留用户选择 Lead 的稳定性、v2.6.7 deterministic policy、native SubAgent 并行/上下文隔离/独立验证，以及 Jev/Laya 的低成本 typed decision 优势；Decision Provider 始终可关闭、可失败、可替换。
