## 已确认的缺陷

RC.2 的 Portable Runtime 运行 `39926717749` 中，macOS ARM64/x64 通过，Windows ARM64/x64 在完整包回归阶段失败；源码 CI `39926717816` 的 Windows Python 3.12 也失败。日志与隔离描述符探针确认：精确终止查询参数不完整时，`read_usage()` 在 `os.open()` 后、进入 `os.fdopen()` 上下文前返回，遗留文件描述符。Windows 临时目录清理因此报 `WinError 32`。

这不是 GitHub 额度不足，也不是需要忽略的清理噪声。macOS 上能够删除打开的文件，不代表没有资源泄漏。

## 窄范围修复

1. 精确终止查询的必要参数在打开日志前验证；缺失身份或不适用来源保持 unavailable，不创建终止证据。
2. 查询、缓存路径和扫描器准备在获取描述符前完成，准备过程失败不再遗留打开的文件。
3. `fdopen` 成功后由文件对象上下文关闭；包装失败时由 finally 释放原始描述符。非预期异常仍传播，不以吞异常伪造成功。
4. 新测试在断言后主动清理有缺陷实现泄漏的描述符，使 Windows 的首要失败仍是资源生命周期断言，而不是二次清理错误。

不改变路由规则、模型、权限、信任、日志发现范围、用量计算、账本 schema 或现场配置。不修改已有 RC.2 归档，也不替换生产安装。
