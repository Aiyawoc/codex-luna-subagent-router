# v2.5.1 — Outcome Collection & Observability

## 目标与边界

保留 Luna / Sol / Astra、luna_only / adaptive、conservative 显式启用、两次 attempt 与成本门。本版修复 outcome 收集稀疏和不可观察问题，不增加第三套路由模式，不引入模型调用、后台服务或未经证实的 Codex hook。

三条用户记录只能证明当前文件记录很少，不能独立证明其他 Worker 均漏记；集中时间也可能是正常批量写入。以下改动让后续问题可定位。

## P0 采集闭环

- conservative 下，派遣前使用 begin 创建不含正文的待完成回执，固化 task family、六轴、请求路由和 scope；返回 receipt_id。
- 完成、拒绝、失败、取消或早停后由 Lead 验收并 finalize；验收不足、身份未知、环境阻塞和 Lead 实质返工记录 partial，不能冒充 verified_pass。
- 只有已核实精确身份和结果的记录可参与校准；请求 profile 不等于观测身份。本版不新增身份读取能力。
- 同一回执幂等写入，重复 finalize 不重复计数，冲突结果报错；并发写入加锁。
- close 前尝试完成回执；记录失败要披露，不得为记日志阻塞停止 Worker。结束前 stats 检查 pending；pending 不被猜测性补写。
- 这是可检测遗漏的协议与本地工具，不是引擎级自动回调；完全跳过 begin 的 Worker 无法被本工具发现。

## P0 项目范围

显式 --project-root 优先；否则从执行命令的工作目录探测 Git 顶层并 hash。非 Git 项目应显式传项目根。提供 --global-scope 访问无项目记录；不同子目录得到同一项目 scope。

begin 固化 scope，finalize 不依赖之后的 cwd。既有 global 记录不擅自改写或迁移到推测的项目。全局安装和全局 adaptive 不等于全局 evidence scope。

## P1 样本复用

A 层保留同 family + 同六轴 + 同 scope + 同 policy + 90 天窗口，降 effort 至少 2 次，安全跨 tier 至少 3 次。

B 层仅同 scope + 同六轴 + 同 policy，至少 5 个有唯一回执的 verified_pass、来自至少 2 个 family；仅允许同模型降一个 reasoning 档，只用于可验证、非 high failure cost、非 architecture。失败组合否决，绝不跨 tier，也不以模糊语义合并高风险样本。

这些门槛是保守策略，不是统计上已证明的成功率。禁止主动制造廉价试跑来凑样本。

## P1 可观察性

route_advisor.py stats 无需六轴；默认汇总全部 scope，可筛选当前项目。显示 outcome / model / effort / scope 分布、无 ID 的旧记录、重复和无效行、未完成回执、稀疏 family、当前可用降档建议和距门槛样本数。

可用建议不等于已发生的路由覆盖；没有执行审计就不报告实际节省金额或已使用次数。旧 global 行只作为 global 历史显示。

## 验收

验证自动 scope、显式 scope、cwd 变化、非 Git、权限和符号链接异常；begin/finalize 幂等、冲突、并发、pending、取消/返工/未知身份 partial；旧 JSONL 兼容、90 天与 policy 过滤、畸形行；A/B 层阈值、失败否决、禁止跨 scope/tier/高风险泛化；stats 与实际 recommend 一致。保留现有路由、安装和 instruction-budget 回归。

合并前运行完整测试、CLI 集成、Manifest 校验。真实 Codex 行为和实际采样覆盖率仍需要升级后的真实任务验收，不能用单元测试替代。
