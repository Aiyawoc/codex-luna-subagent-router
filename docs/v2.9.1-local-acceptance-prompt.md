# 交给本机 Agent 的 v2.9.1-rc.1 验收提示词

```text
请验收当前仓库 upgrade/v2.9.1-hook-compat 分支的 Agent Router v2.9.1-rc.1。
用户已经授权升级，不再重复询问“升级还是全新安装”。保留已有选择，不擅自全新重装或切换安装方式。
先读 docs/v2.9.1-hook-compatibility.md 及 Core references/hook-compatibility.md。

1. 只读基线
识别 OS/CPU、Desktop 完整 build、真实执行 backend、当前会话是否本地编排、Router 安装位置/版本/方式与有效 scope。
不要用 PATH 中独立 CLI 的版本冒充 Desktop 内置版本。
盘点 hooks.json、内联 TOML、用户/项目/插件来源，运行 diagnostics，不 refresh、不写信任。
只保留脱敏 metadata，不输出 prompt、源码、完整 transcript、账号、密钥或信任哈希。

2. 受控升级
.tmp/v291-dist 中为 macOS ARM64 完整候选包；.tmp/v291-plugin 中为默认插件与显式 lifecycle 变体。
只使用匹配平台/CPU且 SHA256 校验成功的包，不把源码压缩包当便携包。
先在隔离 CODEX_HOME 复验 doctor --verify、安装、升级及 staged preflight。
实际升级前备份配置、全部账本与 usage.hook-state，记录哈希，确认没有活动 Worker。
已有完整包就按完整包 upgrade，不为测试插件而迁移生产入口；已有插件就使用既有单入口机制。
未安装时停在只读报告，不擅自全新安装。保留明确 off、摘要选择、路由模式、并发及校准设置。

3. Host 能力与信任
四事件为兼容基线。只有当前 Host 明确支持 Interrupt/SessionEnd，才提出启用可选事件。
--hooks-supported 和 --lifecycle-hooks-supported 都是操作者声明，不是探测结果。
先 dry-run 审查差异，再通过客户端正常信任流程；确需用户点击时才请求协助。
不得写 trusted_hash、修改信任数据库、绕过禁用 hooks 或管理员策略。
无法证明本地 command hooks 可用时保持关闭/手动模式，标记 NOT VERIFIED，不猜测支持。

4. 真实 Desktop 用例
使用新建专用测试项目和测试会话，不修改生产代码或既有会话。
A. 主线程正常完成：核对 UserPromptSubmit/Stop 的实际触发、handler receipt、账本与摘要。
B. 只读 Worker 自然完成：核对子/父身份、SubagentStart/SubagentStop 与用量，不以角色名证明真实模型。
C. 同 Worker 复用：确认增量区间独立，历史 finalized 记录不因后续活动增长。
D. 主线程真实中断：核对精确 session/turn 的 Interrupt，最终计数缺失仍为未知/部分；晚到 Stop 不污染旧账。
E. SessionEnd：只对专用测试会话使用客户端正常结束入口，不关闭正在工作的应用或归档既有会话；不猜 turn 或质量通过。
F. silent/brief/detailed：silent 仍采集、自动 preview 不读日志；升级保留既有选择，错误警告仍可见。
G. 停用/回退：只在隔离目录复验，无第二套账本、双入口或信任写入，旧账本可读且新增 sidecar 保留。
默认四事件插件不得直接修改包内 hooks。测试六事件变体必须走完整迁移和审查，两种入口不能同时生效。

handler receipts 只证明入口运行过，不能单独证明来自某个 Desktop build。
需要当前桌面会话实际触发的独立证据；合成 stdin 和独立 CLI 测试分别标记 synthetic/CLI。

5. 交付
写入脱敏验收报告，逐项 PASS/FAIL/NOT VERIFIED，记录 build、安装方式、事件身份摘要、耗时、完整度和回退结果。
不为完善统计继续模型回合，不无限轮询、不扫描所有会话、不编造缺失计数。
问题先保留可复现证据，修复后重跑相关用例和完整回归。
本任务不自动发布 Stable；Desktop 现场验收不能替代另外三平台发布门，也不能替代真实工作负载收益对比。
```
