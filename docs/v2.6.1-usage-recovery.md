本轮承接已合并的 v2.6.0 私有 Python 运行环境，完成统计修复步骤 2–5。保留 Luna/Sol/Astra 路由、并发上限、outcome 判定、token 原始整数、权限与 hooks 信任边界；不清空旧账本，不估算账单。

## 证据与范围

维护者提供的是 stats 的 400 行展示输出，不是原始 rollout。它显示读取预算耗尽、缺少本轮边界、起点/日志定位不可用、三个重复 session header 拒绝以及笼统 preview 错误。实现针对这些分支与可验证代码缺陷；回归使用合成结构，不能声称已经逐条修复维护者的真实历史记录。

官方 hooks 文档明确 transcript_path 仅为便利字段，transcript 格式不是稳定 hook 接口。新的变体必须有结构证据；不通过角色标签推断模型、不以重复头为理由放开线程身份校验。

## 步骤 2：边界与可续读解析

`UserPromptSubmit` 保存允许目录内的明确日志 locator；日志头尚未刷盘时也不丢失 locator，单独记录 boundary_reason。缺少路径显示 transcript_path_missing，不再把它等同于“未登记开始”。真正无该 session/turn 记录仍报告 turn_not_registered，不凭生命周期累计补本轮。

读取器接受精确 `turn_context.turn_id`，也接受结构化 `task_started/turn_started.turn_id` 作为轮次边界；后者不证明 model/effort。首次匹配目标后，遇到另一轮 start/context 即结束历史目标区间。只匹配结束事件而没有开始身份不能补造轮次。

为每个明确日志和查询保存可删除的数字解析缓存：身份投影、计数基线、已累计数字、观察路由、结构化活动 ID、字节偏移和哈希。缓存位于 `<usage 文件名>.read-cache/`；不保存 prompt、回复、源码、原始日志行或绝对路径。只有正式账本保存对外快照，缓存不能当成账单或独立用量叠加。

首次或失效查询仍从头建立可信基线；每次受字节/时间/单行预算限制，下一次对同一查询从已验证偏移继续。不是对所有新轮次直接跳到尾部，也不是保证任意大日志一次完成。达到预算时同时保留 read_budget_exceeded 和 turn_boundary_unreached；只有实际读完仍未匹配时才报告 turn_boundary_missing。bytes_read/diagnostics.bytes_scanned 现在是该查询已扫描的字节偏移，不是本次物理 I/O 或 token 数。

缓存绑定版本、查询、文件 device/inode、大小、mtime、首行摘要和偏移前 512 字节锚点。缩短、同大小修改、头/锚点变化或缓存损坏会重新解析；起止 cursor 仍单独验证。该优化假设原日志是可信的追加日志，并非对任意中部篡改的逐字节全文件认证。排查非追加修改时，在 hooks 空闲时删除对应 `.read-cache` 目录后从原始日志重新校验，不能删除正式 usage/outcome 账本。

读取期间文件继续增长会保留 source_advanced_during_read；下次复核再读新增部分，不把本次起始长度当成最新终态。单行超过 2 MiB 仍拒绝/降级，不盲目提高预算。

## 步骤 3：重复会话头

同一 `session_meta.id`、规范化 parent、创建边界、ordinal、fork/history lineage 均一致时，将第二个头视为重复元数据。cwd、描述、CLI 版本等可变信息不是重新计费起点。重复头不重置累计基线、不重复添加 token，仅记录 repeated_session_header 信息。

id、parent、创建边界或继承关系冲突时报告 conflicting_session_headers，保留不可用状态。直接 parent 与嵌套 thread_spawn parent 可以等价；两者同时存在却冲突则拒绝。没有维护者原始三个 Sol 日志，不能断言它们全部属于可兼容同身份重复头。历史 multiple_session_headers 需显式重新读取后才会改变，stats 不会自行变绿。

## 步骤 4：受控复核

Stop 和 SubagentStop 保持一次有预算采集；不 sleep/poll、不启动守护进程、不触发额外模型轮次。下一次自然 UserPromptSubmit 先保存新轮起点和旧轮/旧子线程终点，释放账本锁后对最近旧轮最多复核一次（解析预算约 0.8 秒，I/O/锁开销另计）；失败不阻止新请求。它不是后台异步任务。

新增显式 refresh，只处理调用者指定会话且与当前 scope 匹配的已登记记录，按保存的 locator 读取，不搜最新日志、不扫描其他会话。每批默认 20 条、时间预算 8 秒，每次单文件默认 64 MiB；上限 100 条、30 秒、每个文件每次 512 MiB，单行仍为 2 MiB。时间是读取检查的软预算，不是外部 I/O 的硬实时保证。

已封存轮次只有 refresh 或 collect --refresh-sealed 才复核，封存状态不变。旧主线程用精确 turn ID 和可用终点；旧子线程必须有保存的 end cursor，或紧接下一已登记轮次的有效 child 起点。不能跳过边界未知的中间轮次。没有可靠旧子线程终点时保留旧数字并标 historical_child_end_missing，禁止读到今天的累计用量来补过去。

每个查询重新生成/替换最新快照，不将刷新结果叠加到已有总量。源暂不可读或新值反而更少时保留旧快照，标 stale_previous_snapshot 并保留本次真实原因。质量 outcome 不因此变更。不能把未关联子线程存在的合计标为完整。

## 步骤 5：stats / preview 诊断

stats 保持只读，不打开 rollout 或刷新缓存。主/子逐条显示身份、scope、阶段、开始时间、快照更新时间、reader 版本以及“已保存快照，非实时状态”。JSON 增加 diagnostics：reader_version、legacy_snapshot、retained_previous_snapshot、snapshot_age_seconds、bytes_scanned、boundary_reason。没有 provenance 的旧记录显示 legacy/unknown；年龄仅是保存快照的年龄，不证明线程仍在运行或已经失效。

preview 只用于当前活跃轮次；新增 --json，区分 no_active_turn、ambiguous_active_turn、turn_not_registered、turn_not_active、scope_mismatch、token_accounting_disabled、main_accounting_not_enabled、invalid_identity 等。失败退出 2；不猜最后一个 session，也不输出原始异常中的用户内容。

## 本机验收命令

使用**实际安装位置**下的 `bin/router`；Windows 将入口换为 `bin/router.cmd`。下例均从工作项目执行，ID 替换为 stats 中的真实值，不把“示例 ID”当成会话。沿用 Agent 提示词安装完整包，不用系统旧 Python 执行脚本。

```bash
# 只查看已有记录。旧全局记录可用 --global-scope；项目记录用其实际项目 scope。
/path/to/skill/bin/router turn_usage stats --session-id ACTUAL_PARENT_ID --json
/path/to/skill/bin/router turn_usage stats --current-scope --phase sealed --limit 20 --json
/path/to/skill/bin/router token_usage stats --parent-id ACTUAL_PARENT_ID --json

# 当前项目：先复核子线程生命周期快照，再复核该父会话的本轮增量。
/path/to/skill/bin/router token_usage refresh --parent-id ACTUAL_PARENT_ID --limit 20
/path/to/skill/bin/router turn_usage refresh --session-id ACTUAL_PARENT_ID --limit 20 --json

# 只复核一个旧主轮次；不会把它改回活跃。
/path/to/skill/bin/router turn_usage refresh --session-id ACTUAL_PARENT_ID --turn-id ACTUAL_TURN_ID --json

# 明确选择旧 global 数据时（两种 helper 的参数位置不同）。
/path/to/skill/bin/router token_usage --global-scope refresh --parent-id ACTUAL_PARENT_ID
/path/to/skill/bin/router turn_usage refresh --global-scope --session-id ACTUAL_PARENT_ID --json

# 精确当前轮次预览；不用于已结束的历史轮次。
/path/to/skill/bin/router turn_usage preview --session-id ACTUAL_PARENT_ID --turn-id ACTUAL_TURN_ID --json
```

主 helper 的 --project-root 跟在子命令后；子 helper 的 --project-root 是子命令前的全局参数。refresh.processed 表示尝试复核条数，不代表全部 complete。大日志观察 bytes_scanned 是否递增，必要时再次显式执行同一个 refresh；不要无限自动循环。源丢失、身份冲突或没有可靠区间时应停留在 partial/unavailable。

全量安装新包并按第 6 项重新审查 hook 定义（hook version 2.6.1）。旧 v1.0 账本可读，不迁移/清空；新主轮次写 1.1 并保存终点，刷新采用追加快照。旧版读取器不保证识别新字段，降级前应保留整套账本备份，不能靠删除新记录进行兼容。
