# Agent Router v2.9.0-rc.2 — Narrow Fix Acceptance

Date: 2026-10-05

## Why RC.2 exists

RC.1 field acceptance found one reproducible Stable blocker in the release-package upgrade preflight.

When an existing complete-package installation had Router-managed Token Accounting hooks that correctly pointed at the installed copy, running `inspect_guided_install --install-mode upgrade` from a newly extracted staging package built the expected handler from the staging copy's `__file__`. The strict handler comparison therefore reported all four valid installed hooks as missing and reopened Q5.

The actual upgrade did not rewrite the hooks, and the installed-copy preflight recognized them correctly. The bug was the read-only staged preflight identity calculation.

## RC.2 change

Upgrade preflight now derives expected Router-managed hook handlers from detected existing complete-package installation roots.

The change is deliberately narrow:

- a valid handler pointing at the detected installed copy is current;
- a handler pointing at the staging copy is not accepted merely because it has the Router owner marker;
- missing, duplicate or otherwise mismatched Router handlers remain stale;
- native-plugin ownership remains on the existing plugin-specific path;
- no hook definition, trust store, ledger or routing configuration is mutated by inspection.

## Automated gates

The exact RC.2 publish commit must pass:

- full unit/integration suite;
- both positive and negative staged-upgrade hook identity regressions;
- Manifest exact tracked-file coverage;
- Router Arena;
- Windows x64 complete package + plugin smoke;
- Windows ARM64 complete package + plugin smoke;
- macOS x64 complete package + plugin smoke;
- macOS ARM64 complete package + plugin smoke;
- SHA256 verification for all eight release archives.

## Required local re-test

Use the released RC.2 complete package, not a source checkout.

With an existing installation configured as:

- `token_accounting=on`;
- `token_accounting_scope=main_and_subagents`;
- `token_accounting_collection=hooks`;
- all four Router-managed hooks pointing at the existing installed package;

run the same upgrade inventory from both:

1. the newly extracted RC.2 staging package;
2. the installed RC.2 package after upgrade.

Both must report the same four current events:

- `UserPromptSubmit`;
- `Stop`;
- `SubagentStart`;
- `SubagentStop`.

Q5 must not be pending solely because the preflight executable came from the staging package.

As a negative check, a Router-owned handler that points at the staging copy while a different installed copy is detected must still be treated as stale.

## Remaining v2.9 field acceptance

RC.2 does not convert RC.1 evidence gaps into PASS. Real Host structured events, PTC positive-path evidence, natural Worker reuse, Post-Stop freeze, real interrupt isolation, fixed-workload benchmark data and native-plugin Host loading remain subject to `docs/v2.9.0-rc1-acceptance.md` and the v2.9 roadmap.

Capabilities without exact-version real Host evidence remain `unknown`; unavailable scenarios remain `NOT VERIFIED` rather than being inferred from synthetic tests.

## Stable decision

RC.2 removes the RC.1 confirmed blocker only if the released package reproducer above passes. Stable still requires no new Core regression and no authority-boundary violation. Missing evidence may remain explicitly unclaimed where the Stable release makes no corresponding support claim.
