# Agent Router v2.9 Fixed-Workload Benchmark

The benchmark is an observational acceptance tool, not a production tuner.
It compares fixed workloads across Host default behavior, Router Luna-only and
Router adaptive routing while keeping missing evidence explicit.

## Workloads

The ledger accepts these fixed IDs:

1. `micro-known-edit`
2. `parallel-read-scan`
3. `bounded-implementation`
4. `deep-debug`
5. `high-context-scan`
6. `independent-review`
7. `worker-reuse`
8. `interrupt-isolation`

Each workload should use the same repository baseline, acceptance criteria,
Host/backend/version, permissions and fixture for all compared variants.

## Variants

- `host_default`
- `router_luna_only`
- `router_adaptive`

Do not silently retry a failed variant with another policy and then record only
the successful retry. Retries and Workers are separate observed metrics.

## Evidence fields

Each run may record:

- pass / fail / incomplete;
- execution primitive;
- total Token count;
- end-to-end elapsed milliseconds;
- tool-call count;
- Worker count;
- retry count;
- cost with an explicit source;
- evidence coverage: full / partial / unknown.

Cost is accepted only when the source is either a billing export or a
request-level estimate. Receipt-interval estimates whose request pricing
boundary is unknown must not be converted into benchmark cost.

The ledger intentionally contains no prompt text, tool result text, local path
or free-form notes.

## Record one observation

```bash
router benchmark_store record \
  --workload-id parallel-read-scan \
  --variant router_adaptive \
  --backend codex_desktop \
  --host-version <exact-host-version> \
  --outcome pass \
  --execution-primitive native_parallel_tools \
  --total-tokens <known-total> \
  --elapsed-ms <known-ms> \
  --tool-calls <known-count> \
  --workers <known-count> \
  --retries <known-count> \
  --evidence-coverage full \
  --confirm --json
```

Omit a metric when it is genuinely unknown. Do not enter zero as a substitute.

## Read statistics

```bash
router benchmark_store stats \
  --backend codex_desktop \
  --host-version <exact-host-version> \
  --json
```

Statistics average efficiency metrics only over passing runs with that metric
known. Failed runs still reduce the observed success rate.

## Compare to Host default

```bash
router benchmark_store compare \
  --backend codex_desktop \
  --host-version <exact-host-version> \
  --baseline host_default \
  --json
```

A comparison may become `eligible_for_review` only if:

- both sides have passing runs;
- all passing runs used for the comparison have full evidence coverage;
- the Router variant's observed success rate is not below baseline;
- at least one of Token, latency or cost is comparable.

This is still not causal proof and never changes routing automatically.

## Release interpretation

Synthetic/unit-test benchmark rows prove only schema and aggregation behavior.
Stable claims about quality/cost/latency require real Host runs on a frozen
workload. If a metric cannot be measured reliably, leave it unknown and report
the evidence gap rather than estimating around it.
