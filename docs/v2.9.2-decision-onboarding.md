# Agent Router v2.9.2-rc.1: 可选决策模型供应商与安全 API Key 引导

日期：2026-10-29。候选分支：`feature/v2.9.2-decision-onboarding`。基线 `581eda21f8e310a52015ebd52156ae92bfdbf66d`（v2.9.1-rc.4）。本版不修改当前主 Agent、Worker 模型映射、历史账本、用户安装与 Trust。不是 Stable。

## 目标与用户体验

安装盘点新增 **Q7：是否启用可选决策模型？**

1. 默认 **否**：原确定性 Advisor 不变，不写密钥、不访问计费 API；记录用户明确关闭，后续升级不重复询问。
2. 用户明确选择 **是**：供应商 OpenAI Decisions、TypeSafe JEV、JEV 本地 /ask 或兼容 HTTP；选择安全密钥来源；明确提示独立 API 计费，先配置 API Project 预算。
3. Keychain/Credential Manager：本机有 TTY 时隐藏输入并二次确认，借助原生系统 API 保存。配置文件只记录 `credential_source=keychain` 和作用域的非敏感标识。Windows 和 macOS 都不通过 CLI 参数传递密钥。没有支持的 OS vault 则选择 env。
4. 环境变量：配置只记录变量**名称**，不接受 Secret 内容。需将变量安全注入实际 Codex/Router 进程；Terminal 中临时 export 不等于 Desktop 可读取。
5. 以后任何时候都可执行同一向导，选择更换供应商或关闭，原有路由及账本不被清除。

## 使用方式

使用 **当前完整包**，而非 GitHub 自动源代码 ZIP。安装后：

```bash
# 安装预检（只读；仍先选择 upgrade/fresh）
bin/router inspect_guided_install --install-mode upgrade --json

# Q7 独立交互向导；只在本机有 TTY 的终端中输入 Key
bin/router configure_decision_engine --scope user --guided

# 项目级独立引导
bin/router configure_decision_engine --scope project --project-root /path/to/project --guided

# Agent 非交互模式：仅记录密钥环境变量名称，不采集密钥
bin/router configure_decision_engine --scope user --provider openai_decisions \
  --credential-source env --api-key-env OPENAI_API_KEY --json

# 明确关闭；非交互、幂等
bin/router configure_decision_engine --scope user --disable --json
```

如果出于本机调试需要从 CLI 直接选择 Keychain，不通过 chat 或 CLI 参数传送 Key：

```bash
bin/router configure_decision_engine --scope user \
  --provider openai_decisions --credential-source keychain --store-key
```

如果使用 Mac Desktop，优先选择系统 Keychain；系统可能要求用户许可读取，这属于 OS 授权过程，而不是 Router 自行提高权限。密钥不会出现在配置文件、事件日志、对话或 Git。**不要把 API Key 作为 `--api-key` 参数传入任何工具**。

## 契约与故障行为

- OpenAI 端点固定 `POST https://api.openai.com/v1/decisions`，型号目前只允许 `gpt-6-luna`。请求使用最小白名单 state 生成的 `input` 和具名 `questions`，将内部 `noul` 转成官方 `predicate`；`score` 仅支持 2–10 有序等级。
- 解析必须接受完整且名称匹配的答案集、严格的概率和模型标识；独立拒绝、重定向、401/403/429、无 Key、超时、数据损坏、输出超界都只会使**该次 Shadow**不可用，不会改变真实 Worker 模型、权限、并发或计划。
- 首次安装、Q7 盘点以及单纯的安全密钥配置**不自动发付费 API 请求**；只有用户明确开启且 Lead 在有证据的 `decision_checkpoint` 调用 `decision_shadow` 时才产生调用。
- Provider usage 的 input、cached input、cache-write、output、total tokens 只是该决策请求的用量，**不进入 Codex 订阅模式的 Worker 用量**。可能的订阅免费 API credits 由实际组织计费决定，Router 不推断余额。
- OS vault 调用失败或环境变量未进入 Desktop 进程，应明确报告 `missing_credential`，不能悄悄回退到另一凭据或另一付费供应商。
- 对照分析必须看整体任务质量、失败重试、实际费用与端到端延迟；不凭借更低单次决策 token 数直接声明 Router 已节约成本。

## 现有用户迁移

对没有 `decision_engine.setup_completed` 的旧版关闭状态，升级盘点会明确显示 Q7 待选择；**旧版网络惰性的 `openai_decisions` 占位配置即使标记 enabled，也必须重新明确确认，否则不会开始新的付费 API 请求**。既有已启用的 JEV/HTTP 供应商不自动重选、不丢 endpoint 或环境变量。只有用户明确完成新 OpenAI 引导后才设置标记。旧 Core 中 JEV/HTTP 协议继续兼容，但官方 Decisions adapter 使用单独映射，不把旧 `state+questions` JSON 直接发送到新端点。

## 验证边界

使用本地 Mock/隔离配置验证官方 GA 类型映射、401/429、timeout、refusal、重复与未知 answers、TLS/endpoint、无密钥不联网、凭据不落盘、首次／升级 Q7、后续再次引导，以及在 Shadow 中不改变生产路由。

真实 API 认证和一次 `gpt-6-luna` Decisions 请求已由用户在此前独立终端成功执行，但本版不重复消费 API Key，也不把那次请求称为新版完整集成验收。真实 Host 的 Keychain 授权、内核行为及生产改善仍需后续现场验证。OS vault 访问测试不能在 CI 中读写用户真实系统钥匙串。
