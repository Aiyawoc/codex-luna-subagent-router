# Agent Router v2.9.0 — Stable Acceptance

Date: 2026-10-05

## Release position

v2.9.0 Stable ships the reliability, Host-evidence and observational benchmark layers developed through RC.1–RC.3 without expanding authority beyond evidence actually observed.

The Stable decision follows the v2.9 roadmap rule: automated release gates must pass, and real-Host acceptance is required for P1/P2 capabilities **claimed as supported**. Unknown evidence remains unknown.

## Automated release gates

The final Stable commit must pass:

- full unit/integration suite;
- exact tracked-file Manifest coverage;
- Router Arena;
- Windows x64 / ARM64 complete-package build and smoke;
- macOS x64 / ARM64 complete-package build and smoke;
- within each complete-package smoke, install Router-managed hooks and re-run upgrade preflight from the separate staging package, requiring all four Q5 events with Q5 not pending;
- native-plugin migration/deactivate/rollback smoke on all four targets;
- SHA256 verification for all four complete and four plugin archives.

## Real-Host field evidence

Field acceptance on Codex Desktop 26.930.31730, macOS 26.5.2 arm64 established:

- complete-package install/upgrade and package integrity;
- read-only diagnostics with no trust or ledger mutation;
- fresh Worker natural completion;
- natural reuse of the same completed Worker with an independent child turn and exact-cursor incremental accounting;
- observed finalized historical turn remaining frozen after later activity;
- real Host interrupt transition from running through interrupt request to terminal interrupted;
- unavailable Worker usage remaining null/unavailable rather than zero;
- RC.3 staged upgrade preflight correctly identifying all four installed Router-managed hooks, with `needs_question=false`, no pending Q5 and byte-identical config/ledger state;
- RC.3 installed preflight agreeing with the staging preflight after upgrade.

Some lifecycle usage snapshots remained partial because the rollout reader did not observe every terminal transcript event. This is retained as evidence coverage, not rewritten to full.

## Why missing benchmark rows do not block this Stable

`docs/v2.9-benchmark.md` requires real frozen-workload evidence for **Stable comparative quality/cost/latency claims**. v2.9.0 makes no such claim and does not auto-promote any benchmark variant. The benchmark feature itself has schema, aggregation, failure-rate and no-auto-routing regression coverage.

If a later release wants to claim that `router_luna_only` or `router_adaptive` is better than Host default on quality, Tokens, latency or cost, that claim must first be supported by real fixed-workload runs on a frozen repository baseline and exact Host version.

## Unknown/unclaimed is intentional

The following may remain unknown or NOT VERIFIED in v2.9.0 without being converted into support claims:

- `sol_medium` / `sol_max` availability for a specific Host version;
- exact SubAgent identity capability evidence;
- Programmatic Tool Calling Host support;
- structured lifecycle event access;
- native usage event capability;
- real Desktop native-plugin marketplace loading/trust;
- comparative benchmark winner/efficiency claims.

Production routing does not infer these from version strings.

## Stable decision

v2.9.0 is **READY FOR STABLE** when the final Stable commit passes the automated eight-package release workflow.

No confirmed RC blocker remains. Remaining evidence gaps are explicitly outside the Stable support claims above and therefore do not require fabricated or synthetic PASS results.
