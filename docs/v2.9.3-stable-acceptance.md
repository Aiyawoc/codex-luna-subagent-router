# Agent Router v2.9.3 — Stable Acceptance / Mac Keychain Crash

Date: 2026-10-29. Release target: `v2.9.3`. Base: tagged `v2.9.2` / main commit `1320f3cd6174d2c892a93d4ce368e8973d817214`.

## Issue and exact root cause

v2.9.2 on macOS ARM64, bundled Python 3.13.15, user-level `openai_decisions` and `credential_source=keychain`: after `SecKeychainFindGenericPassword` returned `status == 0`, native process crashed at `SecKeychainItemFreeContent(data, NULL)` before constructing an HTTP request. Separate test ledger was empty; no API call observed. The supplied field acceptance marked Provider and Shadow **FAIL**, Desktop Host **NOT VERIFIED**.

Apple's function signature is `SecKeychainItemFreeContent(SecKeychainAttributeList *attrList, void *data)`; when no attribute list was requested, argument 1 must be `NULL`, argument 2 is the returned password data. The Keychain item reference remains separately CF-owned.

## Fix and bounded claim

1. Both `_mac_load` and `_mac_save` call one helper with `free(None, data)`, never `free(data, None)`.
2. Free password data only when allocated; release the returned item reference via CFRelease even when cleanup errors; define explicit native ctypes signatures.
3. If native reports nonzero data length with NULL pointer, do not call `string_at(NULL, size)`.
4. Add regression tests using synthetic memory and fake Security/CoreFoundation functions. No live secrets, Keychain ACL changes, environment leaks or new API calls.
5. Continue honoring `mode=shadow`; no new network request, worker route, permissions, trust or paid-provider defaults are added.

Stable status means the narrowly scoped fix and package contracts pass release gates, not a claim that the originally failing user scenario has already passed in production.
