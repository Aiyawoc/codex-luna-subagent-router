# v2.5.3 — Main-turn Token Summary

## 目标

完成模型标签、可解释的完整度、主 Agent 本轮摘要和升级缺项询问。保持 Luna/Sol/Astra、两种路由、并发、conservative opt-in、k/m/b 和既有白名单边界。

## 数据与口径

用户给出的两条汇总记录均观察到 Luna high，三项警告分别是 missing_baseline、non_usage_counter、terminal_not_observed。汇总本身不足以恢复原始缺失区间；实现只修复有效基线被无效事件清空，不隐藏原始不确定性。回归只使用合成日志及匿名数值，不提交用户路径/ID/对话。

主线程只读自身的 rollout token_count，精确 session/turn；起始游标为最后完整行的偏移及哈希，截断或重写降级。根线程不能借用 child 日志，子线程也不能借用 parent 日志。主子新旧轮次不相加，重复 Stop 不累加；新 UserPromptSubmit 封存旧快照。长期复用 child 只计本轮游标后的新增值；无法关联 parent turn 的新 child 不猜归属。

## 安装

第 6 项统一询问是否开启/升级主子统计；操作者确认四个事件支持后配置，不改变平台禁用或信任数据库。旧 token_accounting=on 缺少 main_and_subagents 范围时必须问。inspect_guided_install.py 盘点全部 6 项，缺失不等于明确 off，已明确关闭保持，格式错误不当缺失跳过。

## 验收

完整测试、四组 CI、Manifest、安装幂等和升级保留。主线程起点缺失、跨轮、重复事件、日志重写、计数不一致、并发读写失败均不能伪造零或阻塞正常停止。显示完整度只覆盖已观察/已登记线程，不承诺引擎全量计费。

## 官方依据与限制

- https://learn.chatgpt.com/docs/hooks （UserPromptSubmit/Stop 的 turn_id、systemMessage、信任和不稳定 transcript 接口）
- https://github.com/openai/codex （线程局部 token_count、usage total/last 与 context-window synthetic updates）

无后台守护程序、无额外模型调用、不更改最终回复正文。结束时日志可能还没有终止事件，显示待确认；可在下一请求前手动 collect 复核。合成/CI 测试不是用户桌面端自然触发验收；不同客户端格式仍以真实数据为准。
