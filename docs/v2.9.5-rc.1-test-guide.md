# Agent Router v2.9.5-rc.1 · 本机 Agent 升级与策略验收

版本：`2.9.5-rc.1`。目标环境：已安装的 macOS Apple Silicon 完整 Skill，用户级或项目级有效 `routing.json`。

## 可以直接交给本地 Agent 的执行指令

**任务目标：** 受控升级当前 Agent Router 完整 Skill 至 `v2.9.5-rc.1`；显式使用增强后的 `adaptive`（约30%的观察目标）；在完全隔离的测试 HOME 中对比新 `adaptive_aggressive`（约50%的观察目标），并提供报告。**这些百分比不是强制配额，本轮无需也不得制造真实 Worker 用量。**

**启动规则：**

1. 先检查是否已安装目标版本且 `doctor --verify` 通过：如果是，不再安装，直接做缺失验收。检查当前项目是否有项目级配置覆盖用户级；先用只读方式确定真正生效的作用域。
2. 若检测到多个 Skill 安装位置或 Plugin 已占用当前作用域，停止安装并报告冲突，不擅自禁用插件或修改 Host trust。
3. 检查其他活跃 Codex Worker 是否仍在执行。如果存在，保留并仅报告阻断；不得自行关闭其他会话。
4. 严禁把 API Key 粘贴到对话，不运行 `--guided`／`--store-key`，不访问 Keychain Secret，不创建 SubAgent，不调用计费 Decisions API，也不访问第三方雷达。所有规划测试均带 `--no-decision-api --no-radar`。
5. 不主动调用 `new_context`。每个阶段完成即记录证据；最终直接输出验收结果，不能只回复“已了解规则，接下来做什么？”。

REPO=/Users/ethen/同步空间/CODE/AI/codex-luna-subagent-router

在真实用户 macOS 环境下执行；**不要用 CTR/MCP 的隔离 `$HOME` 误装到临时目录**。若 `$HOME` 不是 `/Users/ethen`，不要盲目执行 `--global`，改用实际用户的可见 Terminal 或能明确指定安装目的地的受控环境。允许只读检查及创建项目内被 Git 忽略的证据目录。

**A. 预检和备份**

- 检查 `$INSTALLED/VERSION`、实际安装路径、`plugin_control inspect`、有效路由模式，以及已有 `decision_engine`、`evidence_calibration`、`token_accounting`、`radar_selection` 的非秘密设置。
- 将安装文件完整性、配置文件的 SHA256、Git 仓库 HEAD/staged/unstaged 状态记录到 `$REPO/.tmp/v295-rc1-local-acceptance/`。必要时做0600权限备份，但不将包含私密配置的备份提交Git或贴到聊天。
- **不要修改**用户根仓库已有的未提交文件、账本或 `AGENTS.md`。用户级和项目级配置作用域只选择实际需要更改的那一层。

**B. 可信发行包**

从 GitHub 的 `v2.9.5-rc.1` 正式 Release 资产下载 `router-2.9.5-rc.1-macos-arm64.tar.gz` 及同名 `.sha256`，核对归档 SHA256 和 `SHA256SUMS`。必须检查是正式发行的完整包，不是网页 Source code ZIP，不接受未验证的缓存文件。

在项目的 `.tmp/v295-rc1-local-acceptance/extracted/` 解压；运行新包的 `bin/router doctor --verify`，确认其 `VERSION` 和 `TARGET=macos-arm64`。若已安装当前版本且完整性正常则跳过升级，不要重复替换。

只有确认已无活跃Worker、包完整、安装目标是正确的用户目录后，执行：

```bash
export CODEX_HOME=/Users/ethen/.codex
export CODEX_SKILLS_DIR=/Users/ethen/.agents/skills
export CODEX_AGENTS_DIR=/Users/ethen/.codex/agents
# 下面使用解压后的新完整包，而不是旧的 INSTALLED
"$EXTRACTED/codex-luna-subagent-router/bin/router" install --global --install-mode upgrade
```

保存安装结果中的 `previous_package` 备份目录；升级完成运行**新安装路径**的 `doctor --verify` 和 `inspect_guided_install --install-mode upgrade --json`。不得删除安装程序生成的previous备份，直到现场验收完成。

**C. 路由模式配置，Keychain不重录**

首选 `adaptive` 进行自然任务观察，`adaptive_aggressive` 暂时只进行完全隔离的离线对照，除非用户另行明确要求将生产模式切换到aggressive。

如果有效配置来自用户级：

```bash
"$INSTALLED/bin/router" configure_guided_install \
  --delegation none --routing-scope user \
  --routing-mode adaptive --request-user-input none --dry-run --json
```

先检查预览是否只包含预期的 `routing_mode` 变化及可保留的旧默认字段。如果合理，再去掉 `--dry-run` 执行一次，随后重复调用一次验证返回 `unchanged`。如果有效配置来自项目级，改用 `--routing-scope project --project-root "$REPO"`，**不要同时修改用户级和项目级**。

配置前后的语义差异仅允许显式模式切换，以及本版必要的无破坏性默认字段。`decision_engine` 的provider、Keychain引用、`automatic_checkpoints`、30秒总/网络超时、`token_accounting`、hooks与 `radar_selection` 均须保留。**不要启动雷达网络选型；其站方授权仍需独立确认。**

**D. 离线测试，两种模式均验收**

在 `$REPO/.tmp/v295-rc1-local-acceptance/offline-home/` 创建专用 `CODEX_HOME`，只写入最小无密钥路由配置，分别设成 `adaptive` 与 `adaptive_aggressive`。采用 `--global-scope` 的 `route_advisor plan` 以及 `--no-decision-api --no-radar`，`--open-workers 0`、`--runtime-health healthy`。

至少验证以下三个真实代码入口场景（任务JSON使用合法六轴和规范化相对路径）：

| 合成场景 | adaptive | adaptive_aggressive |
| --- | --- | --- |
| 一个bounded、medium推理、可交付的同层实现工作包 | SubAgent | SubAgent |
| 一个bounded、shallow推理、独立实现并局部测试的同层工作包 | Lead | SubAgent |
| 一个无写入、shallow、low-context的机械只读查询 | Lead/本地工具 | Lead/本地工具 |

再检查：`micro` 不委派、没有可转交上下文不委派、`luna_only` 不跨模型、任务间读写冲突不放行、并发3仍有效、旧型号不自动恢复。不要仅用 `ready_worker_ids` 数量推断实际Worker用量。

只读验证 `report` 中的 `delegation_policy` 或等效规划元数据：`adaptive` 目标0.30、`adaptive_aggressive` 目标0.50，`measured_subagent_usage_share` 仍为null，不得填报实现了30%或50%。

**E. 升级后复核与停止条件**

复核生产 `routing.json` 只有预期变化，Decisions配置和凭据引用原样保留，账本文件未被覆盖，Git原仓库暂存与未暂存差异哈希不变，`doctor --verify` 保持PASS；报告新版本、安装备份位置及两模式离线结果。

出现版本校验失败、安装目录冲突、配置异常、系统权限提示不可见、或者已有活跃Worker时，**停止并报告具体阻断，不进行强制修补或循环重试**。

若升级后核心检查失败，可在确认无活跃Worker后，使用安装结果 `previous_package` 中经验证的旧 `bin/router` 执行 `install --global --install-mode upgrade` 回退，并复核旧版本与配置；不要直接手工移动安装目录或修改hooks/Host trust。
