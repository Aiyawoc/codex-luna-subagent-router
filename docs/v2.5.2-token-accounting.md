# v2.5.2 — SubAgent Token Accounting

基线 main v2.5.1：`e735dba92ebc636fb98e5d861177c49c444a2766`。本版按用户要求加入子 Agent token 统计，不修改三层路由、并发、两次 attempt 和保守校准策略。

## 交付

1. usage_reader.py：受限 JSONL 读取、真实 child ID/父 ID 校验、继承边界与增量计数、缓存及推理子项、部分/不可用状态；数据格式不支持时不猜。
2. token_usage.py：独立 opt-in、SubagentStart/SubagentStop、手动 start/collect/attach、相对 locator 复核、按 child 最新快照去重、短格式与覆盖率统计。
3. configure_token_accounting.py：第 6 个安装选项，配置单字段、保留自定义 hooks、短超时、备份与异常回滚；不自授信任、不越过 hooks 禁用。
4. finalize 关联用量但不改变质量 outcome；stats 同时给出已有 outcome 和 token 数据。普通 Luna Only/off-calibration 同样可独立统计。

## 显示

四项固定为：总量 / 输入 / 输入中的缓存命中 / 输出；示例 `45k / 42k / 30k / 3k`。总量含缓存，缓存不重复相加；reasoning 是 output 子项。小于 1000 为原数，k/m/b 为十进制千/百万/十亿；JSON 永远保存原始整数或 null。

## 风险与不做

不根据自报或字数估算 tokens，不读取父日志替代子日志，不扫描其它会话，不读取 SQLite 或额外调用模型。hook 并不意味着客户端已支持或已信任；必须实机确认。停止时可能未写入 terminal 记录，因此先 partial，finalize 后复核。structured-event adapter 仅适配手动提供的事件文件，不自动订阅桌面内部服务器。

用量账本独立于成功率历史；partial/failed/cancelled 的已发生消耗仍可记录。单 Worker 多个 stop 更新累计值，新线程 retry 独立计数；旧无 token 数据的 outcome 不追补数字。计数不能直接解释为账单或套餐额度。

## 验收矩阵

覆盖 k/m/b 进位、null 与 0、四项口径；累计重复/多请求、父历史隔离、ordinal、缺失基线、计数重置/缺口、尾行/字段缺失；hook exit 0/短 JSON、on/off 解耦、项目 scope、receipt 一对一、幂等并发、延迟复核、安装保留/回滚和未授权 hooks；保留原完整回归与指令预算。

本地与 CI 测试只验证脚本及合成数据。用户 Codex Desktop 的 hook 支持、信任、日志格式、自然触发和覆盖率仍需实机验收。详见 `skills/codex-luna-subagent-router/references/token-accounting.md` 的命令及官方来源。
